# Bilibili AI 编排任务

你会读取候选池 JSON，然后输出一份可直接执行的 B 站内容安排。

核心规则：
- 先排除 commercial 和 restricted_access
- 如果是瑜伽/运动跟练日程，跳过介绍、答疑、档位说明、课程说明、合集介绍、UP 主自述、vlog、直播回放等非跟练内容
- 两周内用过的视频不要重复
- 最新优先，但不要把一周排成同一 UP 或同一节奏
- 多样性要参与判断：来源、主题、强度、时长都要尽量拉开
- 主题贴合度高于机械的新旧排序
- 候选不足时，明确说明缺口，不要硬编

下面 `OUTPUT_FORMAT` 标记之间的内容是输出格式的唯一来源：SKILL.md 只指向它、运行时生成的 `prompt.md` 直接把它整段嵌进去。改格式只改这一处，不要在别的文件里另写一份。

<!-- OUTPUT_FORMAT:BEGIN -->
## 输出格式

请严格按下面五段输出 Markdown，顺序不要调整。第 5 段没内容就整段省略。用用户的语言回复。

```markdown
## 使用的 skill 与路径
- Skill：{skill 名称}
- Skill 注册路径：{注册路径}
- 真实项目根目录：{项目根目录}
- 本次运行产物：{run 目录}
- 读取的偏好与去重状态：{user_memory.json / state.json 等}

# {主题}安排（{起始日期} ~ {结束日期}）

## 编排思路
一段散文，不要用 bullet。必须说明：如何落实这个主题最近几次记录里的状态与身体约束、哪里让主题贴合度盖过了新旧排序、创作者如何分散、14 天去重排掉了什么。

## 每日安排

### 周一｜{日期}｜{槽位}
- {标题}
- {播放链接}
- {UP 主}｜{发布日期}｜约 {分钟} 分钟
- {结合当天槽位与用户约束的推荐理由}

...

## 需要说明的
只在确有问题时写：抓取报错、限频、候选偏少、内容偏旧、工具本身的缺陷。
```

不要把候选数量、source_counts、各类过滤计数搬进回复，这些已经在 brief.md 里。
<!-- OUTPUT_FORMAT:END -->
